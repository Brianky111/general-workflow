# Project Contract (LEAN) · 报表导出 CLI

- problem: 运营每次要一段时间的订单明细，都得找工程师手写 SQL 再导 CSV。等待通常一天以上，导出口径还每次不同，两个人拉同一周的数据会得到两份不一样的表。
- primary_users: 运营（3 人，会用命令行，不会写 SQL），偶尔是财务对账
- entrypoints: CLI `report-export`，在运营自己的机器上运行
- desired_outcome: 运营自己敲一条命令，得到一个口径固定的订单明细 CSV
- success_signal: 连续两周没有人再为「导一份订单明细」提工单
- delivery_endpoint: implementation-and-tests

| --- | --- | --- | --- |
| 按日期区间导出订单明细 CSV（2026-09-08 原始请求） | 运营机器装好 Python 3.12，能直连订单库只读副本；产物是本地 CSV | 退出码 0，表头固定为 order_id,created_at,channel,amount；行数等于区间内订单数；不得把数据写到本机以外 | 一次真实命令调用 + `pytest -q`；A-01 |

交付终点是 `implementation-and-tests`：本版不承诺打包分发，跑通实现和测试即收尾。

## 范围

- must: 按日期区间导出订单明细 CSV；区间参数非法时拒绝并说明；区间为空时不产出文件
- non_goals: 不做定时调度（运营手动跑就够）；不保留导出历史；不做权限系统，谁能连副本谁就能导；不做导出后自动发邮件（A-05 取消，见 `docs/changes.md` 的 C-02）
- later: xlsx 导出（A-04）、按渠道过滤、按金额区间过滤

## 约束与风险

- constraints: Python 3.12；只读连接订单库副本，不建表不写表；导出文件只落本地磁盘，不上传任何位置
- quality_targets: 单次导出 10 万行内、30 秒内完成。这是选型上界，不是本版验收条件——达不到就换方案，不是判定失败
- risks: created_at 存的是本地时间还是 UTC 决定区间边界含义。最小验证：对边界日各查一条已知订单，比对它落在哪一天
- assumptions: 运营机器能直连只读副本，不需要跳板机

## 架构决策与假设

一页决策表，不写完整 ADR：

| 决策 | 选择 | 驱动 | 代价 / 重评条件 |
| --- | --- | --- | --- |
| 系统形态 | 单进程 CLI | 没有常驻需求，没有第二个调用方 | 出现定时调度或第二个入口时重评 |
| 目录边界 | `src/report`（用例 + 数据适配器），`tests/report` | 只有一个模块，不预设分层 | 出现第二种数据源时拆适配器 |
| 数据所有权 | CLI 不拥有任何数据，只读订单副本 | 避免导出工具变成第二份口径 | 若要缓存导出结果，回到这一行重评 |
| 技术栈 | Python 3.12 + 标准库 csv + psycopg 3.2 | 团队已有；csv 不需要额外依赖 | 需要 xlsx 时会引入新依赖，走变更协议 |

H-01：psycopg 的服务端游标可以在不把结果集全部读进内存的情况下导出 10 万行。
通过条件：导出 10 万行时进程常驻内存低于 200 MB。不成立就改成分页查询并回到上表重评。
