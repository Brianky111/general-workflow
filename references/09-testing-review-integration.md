# 测试、评审与集成

本阶段把 TDD 中的行为证据扩展到模块协作、真实依赖、公共契约和运行风险。测试深度由项目画像和质量目标驱动，不追求平均铺满或 100% 覆盖率。

## 目的与入口

目的：确认当前范围在真实组合下满足验收、架构边界和必要质量目标，并让评审意见有明确的处理归宿。

入口：

- 08-implementation-tdd.md 已完成当前切片的最小行为；
- A-ID、R-ID、Q-ID、架构假设和变更范围可追踪；
- 仓库已有可运行的 unit/test/build/check 命令及基础 CI。

## 测试层次

采用“越靠近业务规则越快、越靠近真实环境越少”的分布，不机械套比例：

| 层次 | 证明什么 | 依赖策略 | 运行时机 |
| --- | --- | --- | --- |
| 单元 | 值对象、规则、状态、不变量 | 无外部资源 | 每次提交 |
| 集成 | 模块与真实数据库/队列/缓存协作 | 隔离测试资源，少 mock 自有模块 | PR 或合并前 |
| 合同 | HTTP/RPC/事件的序列化、状态码、错误码、版本和权限 | 真实边界，供应商可用契约替身 | PR/发布前 |
| E2E | 关键用户从入口到结果 | 生产式组合，数量少 | 合并/发布前 |
| 专项 | 性能、安全、迁移、恢复和可访问性 | 按风险建立环境和数据 | 档位/风险触发 |

## 证据映射

普通项目为每个验收场景建立“行为→证据”映射：

~~~markdown
| A-ID | path | test/evidence | environment | result | artifact |
| --- | --- | --- | --- | --- | --- |
| A-01 | POST /items -> DB -> response | integration + E2E | CI/staging | PASS | run link |
~~~

证据必须包含运行命令、提交/产物、环境和结果；“看过代码”“测试应该能过”不是完成证据。高风险项目再增加独立评审、专项清单和签名/审批，普通项目不因模板缺失而阻塞。

### BDD / TDD 校验

沿用上面的证据映射，核对“权威场景 → A-ID → 实际测试及断言 → 生产入口 → 运行结果”。`AGENTS.md` 指引如何执行校验，校验结论引用真实证据；不按每个需求创建一份 agent 文档或复制场景。

- **语义**：从目标合同的完成边界反查本切片覆盖的结果，再检查 Given/When/Then 与禁止效果是否真正被断言；各模块单测通过不能代替跨模块用户结果。场景遗漏回 02，缺少实现回 08；原始意图歧义或核心目标矛盾回 P0。
- **过程**：核对新增行为在 08 阶段记录的 Red 原因、Green 结果和重构后检查；最终绿色不能倒推出曾经完成 TDD。历史 Red 不可得时如实记录缺口，保留当前回归证据，不编造失败记录。
- **真实性**：检查测试是否实际被发现并执行、生产入口是否注册，以及是否通过跳过测试、弱化断言或平行实现掩盖缺陷。缺少实现回 08，集成或测试发现问题在本阶段修复。
- **指引**：本次改变的模块边界、入口、约束和命令须与适用 `AGENTS.md` 一致；核对权威链接和相关验证命令。可重复的完整性检查尽量自动化，文档勾选或评审者的通过声明不替代测试结果。

普通切片由当前 agent 执行上述校验；高风险边界沿用本阶段的独立评审要求。需要独立评审时提供权威场景、变更范围和可重跑证据，不只提供作者的完成总结；校验指引本身不自动创建多个 agent。

最后一条切片集成后，对照原始请求及已接受变更，逐项验证合同中的全部承诺结果、必要约束和组合路径，复用现有证据映射。测试全绿但仍有结果无法兑现时，不得宣称整项需求完成，也不得修改完成边界来迁就实现；按上述原因回流。发布与任务收尾继续按 99-state-and-handoff.md 的“范围完成与任务结束”执行。

## 集成测试边界

- 使用隔离的测试数据库/队列，迁移从空库执行；每次运行清理数据或使用事务/唯一命名空间；
- 自有模块之间尽量走真实实现，避免 mock 掩盖序列化、事务、权限和连接问题；
- 第三方支付、邮件、身份、搜索等不可控系统可使用官方 sandbox、录制契约或受控 stub，但要另有合同/重试/超时测试；
- 测试真实的组合根、路由、消费者、调度器和配置加载；
- 对并发、重复消息、超时、部分失败和重启至少选择一个最有风险的场景；
- 测试数据不包含真实秘密或生产个人数据。

## 架构约束检查

按 05 阶段的决策验证：

- 模块依赖方向没有反向边和循环；
- 非拥有模块不能直接写入核心数据表；
- 认证、授权、租户和默认拒绝在真实入口生效；
- 异步任务的幂等、重试、死信、顺序和补偿符合决策；
- API/事件版本、错误信封、request ID 和 retryable 语义稳定；
- 配置/秘密未进入源码、日志或错误响应；
- 日志、指标、追踪、健康检查和告警能在测试环境观察；
- 迁移可在空库和代表性旧版本上执行，必要时可前滚/回滚。

可以用静态依赖检查、schema 校验、契约测试或启动探针实现这些约束，但检查本身不能取代端到端行为。

## 风险专项

根据 Q-ID 和风险档位触发：

- 安全：未登录、越权、跨租户、注入、CSRF/CORS、敏感日志、密钥轮换和依赖漏洞；
- 性能：代表性数据量、并发、p95/p99、吞吐、队列积压和资源上限；
- 恢复：进程重启、依赖恢复、重复投递、备份恢复、迁移中断和补偿；
- 兼容：旧客户端/事件消费者、双读双写、弃用窗口和未知字段；
- 可访问性：键盘、读屏、对比度、错误提示和焦点；
- 运营：告警触发、runbook 可执行、request ID 可追踪。

专项测试若失败，先判断是否违反当前范围或质量目标；若只是未来优化，记录后续，不扩大当前验收。

## 评审与集成顺序

1. 作者自检 format/lint/typecheck/unit；
2. 运行集成和合同测试，修复真实接线问题；
3. 对高风险边界安排独立评审或职责分离；
4. 运行关键 E2E 和必要专项测试；
5. 将每条意见分类为当前缺陷、已接受的风险、非目标后续或需求变更；
6. 只有影响当前 A-ID/R-ID/Q-ID、数据安全、公共兼容或发布准备的意见阻塞合并；
7. 合并后重新运行生成产物和最低 smoke，不把本地通过当作集成完成。

评审可以发现遗漏，但不能自行创造新的验收范围。新行为回到需求/范围阶段；架构边界问题回到 05。

流水线按测试层次表的“运行时机”列分层即可，不另立一套。缓存只加速，不改变结果；失败日志、测试报告和产物应可下载。偶发失败要记录并修复，不要简单重跑到绿色。

## Definition of Done

当前批次可进入 10-release-operations.md 的条件：

- 当前范围每个 Must/A-ID 有通过或明确接受的证据；
- 真实入口和关键失败/权限/状态路径已验证；
- 必要集成、合同、E2E 和风险专项测试通过；
- 架构约束、迁移、配置、秘密和观测检查通过；
- 评审意见已分类并关闭/记录；
- 本次涉及的模块指引准确，BDD 场景与测试证据映射已核对；
- 构建产物可追溯到提交和锁定依赖；
- 没有可复现且属于当前范围的阻塞问题；
- 发布、观察和回滚需要的证据已列入清单。
