# 真实代码实现：红—绿—重构

本阶段沿用附件中有效的行为驱动 TDD 机制，但把单位收敛为当前切片中的最小可观察行为。测试的价值在于证明真实生产路径，而不是制造一个容易通过的平行系统。

## 目的与入口

目的：用短反馈循环实现切片行为，保持业务规则清晰、接线真实、每一步可回退。

入口：

- 07-vertical-slice.md 已通过 Slice Ready；
- 目标 A-ID、生产入口、依赖和测试归宿已明确；
- 任何会改变行为、数据、安全或公共兼容的未决选择已解决或被标为阻塞。

## 一个行为一个循环

### Red

1. 从验收场景选一个最小行为点，例如“已登录用户可创建有效项”或“重复任务不会产生第二次扣款”；
2. 写出通过真实入口或真实组合根的测试；
3. 运行测试，确认它确实失败；
4. 判断失败原因是缺少生产实现/接线，而不是测试拼写、环境或错误的 SUT；在现有测试报告或切片证据位置记录 A-ID、测试入口、命令、运行版本和失败原因，Green 后关联通过结果，不为每轮新增过程文档。

如果测试一开始就通过，记录为已有行为或测试没有覆盖目标，先修正测试/范围；不要为了形式强行制造红色。

BDD 场景中的前置、动作、结果和禁止效果决定断言含义；TDD 可把一个 A-ID 分解为多个测试。实现困难时不得通过删除/跳过测试、弱化断言或改写需求获得绿色；测试本身有误时依据权威场景修正并说明原因，需求有误时走 P0/范围回流。

### Green

写让该行为通过的最少生产代码：

- 先实现必要的输入校验、领域规则、端口和适配器；
- 只接入当前切片需要的真实路由、注册、迁移和配置；
- 不提前添加未来字段、通用框架或未验收分支；
- 测试替身只隔离不可控外部系统，核心模块之间优先走真实实现。

绿之后立刻对真实入口发起一次调用，把调用方式和观察到的结果记进切片的 evidence。这是 09
单条门禁的硬条件；在这里顺手做完，比事后回忆一条没跑过的命令可靠。调用不上说明接线还没成立，
回到脚手架或集成边界，不要靠测试绿色代替它。

### Refactor

在绿色保护下改善命名、重复、依赖方向、错误表达和可诊断性。每一小步重新跑相关测试，完成后再跑 check。重构不能悄悄改变验收行为或扩大范围。

这里的重构不出本切片的 write_scope，也不动模块的公开入口和边界。要动边界、跨出 write_scope，或者没有功能切片在推着它的整理，走 00-refactor-path.md：那里要求先有授权和保护基线，再有一条由红转绿的结构检查。

切片改变模块的公开入口、边界、特殊约束或验证命令时，同步更新适用的模块 `AGENTS.md`，并以实际运行结果校正指引。只改实现细节且指引仍准确时，不额外改文档。

### 继续或结束

- 仍有当前切片的 A-ID 行为未覆盖：选择下一个行为点，回到 Red；
- 当前验收和必要失败边界已覆盖：运行更宽的集成/合同测试，进入 09；
- 发现新需求或新风险：记录并回到范围/风险阶段，不在本循环偷偷扩张。

## 真实入口与组合根规则

- 测试调用的路由、CLI、消费者或调度器必须在生产启动时注册；进程内直接调用组合根函数（例如 console_script 指向的 main）算真实入口，另起 subprocess 不是更高标准，只是更慢；
- 依赖注入、配置、迁移和序列化要经过真实组合根；
- 不创建只在测试中存在的 V2、替代服务、假数据库或旁路 handler；
- 测试中使用 mock 时，断言公开契约和副作用，不要只断言 mock 被调用；
- 每个行为至少有一个能证明用户可观察结果的测试；纯规则可由更快的单元测试补充；
- 真实入口无法在测试环境运行时，先修复脚手架/集成边界或明确高风险例外及补证计划。

## 测试边界

| 代码/风险 | 首选证据 |
| --- | --- |
| 纯值对象、状态规则、不变量 | 单元测试 |
| 应用用例与真实数据库/队列 | 集成测试 |
| HTTP/RPC/事件序列化、状态码、错误码 | 合同测试 |
| 关键用户跨多个模块的路径 | 少量 E2E |
| 性能、安全、恢复、迁移 | 风险触发的专项测试 |

覆盖率是诊断信号，不是把未要求的行为变成新范围的理由。

## 提交与范围控制

一个提交尽量有一个目的：一个行为、一个重构、一个迁移或一个工具链修复。提交信息和 PR 描述回链 A-ID/R-ID，说明运行过的命令和已知限制。

遇到邻近问题时走 03-scope-and-nongoals.md 的范围防火墙，不要让顺手重构吞掉当前结果。

## 例外：原型和探索

一次性脚本、技术验证或抛弃式原型可以先缩短 Red/Green，但必须标明：

- 不进入生产入口；
- 不作为完成证据；
- 处理了哪些风险、还缺哪些测试/安全/迁移；
- 转正前的补证条件和删除时间。

## Implementation Ready/Done 门禁

本阶段完成一个切片行为的条件：

- Red 失败原因已确认，或已有行为被准确识别；
- Green 通过且代码接入真实生产路径；
- Refactor 后相关测试和静态检查仍绿；
- 配置、迁移、错误、权限、日志和指标按场景接通；
- 没有未记录的范围扩张或平行 SUT；
- 变更可由单一提交/PR 解释并可回退；
- 进入 09-testing-review-integration.md 所需的集成、合同和 E2E 证据已列出。
