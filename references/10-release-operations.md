# 发布、监控、回滚与运行

本阶段把“代码通过测试”变成可安全交付和可恢复运行的版本。CI 证明提交和产物质量；CD 负责环境晋级、迁移、发布、观察和回滚，两者不能混为一句“自动部署”。

## 目的与入口

目的：以可追溯、可观察、可恢复的方式把当前范围交给真实用户，并在异常时限制影响。

入口：

- 09-testing-review-integration.md 的“当前批次：可以进入 10”已全部满足；
- 已有可部署产物、版本、迁移和环境配置；
- 发布负责人、值班人、观察窗口和回滚权限已明确。

## 环境分级

至少区分：

- **dev/local**：快速开发，数据可丢弃，秘密使用本地安全注入；
- **staging**：尽量接近生产的拓扑、配置和数据规模，运行 smoke/集成/E2E/迁移演练；
- **production**：真实数据和用户，最小权限、审计、备份、告警和值班责任完整。

环境之间不可意外共享生产秘密或个人数据。每个环境记录版本、配置来源、依赖版本和已知差异。

## 构建产物与可追溯性

发布前确认：

- 产物由 CI 从指定提交和锁定依赖生成，尽量不可变；
- 版本号、提交 SHA、构建时间、依赖清单/SBOM 和迁移版本可追溯；
- 镜像/包经过漏洞和许可证检查（按风险档位）；
- 配置和秘密在部署时注入，不打进产物；
- 产物在 staging 验证后晋级同一份，不在生产重新编译。

## 数据库迁移与兼容

每个迁移说明：

- 影响的实体、锁/耗时、索引和容量；
- 是否支持旧代码与新代码共存；
- 展开→切换→收缩（expand/contract）步骤；
- 失败时可回滚、前滚还是执行补偿；
- 备份、恢复点和验证查询；
- 何时删除旧字段/旧事件/旧客户端兼容。

先在 staging 用代表性数据和中断场景演练。不可逆删除、数据重写或隐私操作没有可验证恢复方案时，阻止发布或缩小范围。

## 发布策略

按风险选择：

- 滚动：实例兼容且单次影响可接受；
- 蓝绿：需要快速切换并保留上一版本；
- 金丝雀/灰度：公共、高风险或容量未知，先给小流量/租户；
- 分批：按区域、组织或队列逐步扩大；
- 手工窗口：仅在合规/依赖要求下使用，并保留同样的证据和回滚步骤。

发布前设定停止/回滚阈值，例如错误率、p95、队列积压、关键业务成功率或安全告警。阈值应对应 Q-ID 和观察窗口，不要发布后凭感觉决定。

## CI/CD 流程

~~~text
PR/push
  -> format/lint/test/build
merge
  -> immutable artifact + metadata
staging
  -> migration rehearsal + smoke/integration/E2E
approval or policy gate
  -> canary/batch production rollout
  -> observation window
  -> continue, rollback, or forward-fix
~~~

生产审批可自动或人工，取决于风险和组织政策；无论哪种方式，都要记录谁/什么规则作出决定。

## 监控、告警与观察窗口

发布前确认 dashboard 和告警能按版本、环境、租户/区域（安全允许时）切分：

- 流量、错误率、状态码和依赖错误；
- p50/p95/p99 延迟、资源和实例健康；
- 队列深度、任务年龄、重试和死信；
- 数据库连接、锁、迁移状态和备份；
- 核心业务指标，如创建/支付/同步成功率；
- 日志、指标、追踪可用 request_id/correlation_id 关联；
- 告警有责任人、阈值、通知路径、runbook 和解除条件。

观察窗口覆盖最容易出问题的用户路径和一个依赖/恢复场景。记录开始/结束时间、基线、版本、异常和结论。

## 回滚、前滚与恢复

发布 runbook 要明确：

1. 谁可以暂停流量、切换版本或停止迁移；
2. 代码回滚的命令和前置条件；
3. 数据迁移是可逆回滚、兼容前滚还是备份恢复；
4. 已产生的事件、任务、通知、支付或文件副作用如何去重/补偿；
5. 回滚后如何验证健康、数据不变量和关键业务结果；
6. 用户通知、审计记录和事后复盘负责人。

“重新部署旧镜像”不是完整回滚计划；如果 schema 或副作用已改变，必须有前滚/补偿策略。至少在 staging 演练一次高风险回滚。

## 运行手册与责任

每个服务/worker/迁移记录启动、停止、扩容、依赖故障、密钥轮换、备份恢复和联系人的步骤。值班责任、升级路径和权限不能只存在个人记忆中。

## Release Ready 门禁

发布当前范围前必须有：

- 已验证的不可变产物和版本追踪；
- dev/staging/prod 配置、秘密和访问权限（STANDARD 起；LEAN 的等价物见 00-lean-path.md）；
- staging smoke/集成/E2E 及迁移演练结果（STANDARD 起，或存在真实部署环境时）；
- 备份、恢复点、回滚/前滚/补偿方案；
- 选定的滚动/蓝绿/灰度/分批策略和停止阈值；
- 日志、指标、追踪、健康检查、告警和观察窗口；
- 可执行 runbook、发布人和值班人；
- 没有属于当前范围的未关闭阻塞风险。

Release Ready 证明发布准备完成。若用户的交付终点仅为发布准备，在此记录证据并交接；若已要求发布到指定环境，则在授权范围内发布，保持同一产物晋级，完成观察窗口，并将运行证据带到 11-retrospective-evolution.md。不能用验收台账清空或 Release Ready 代替实际发布与观察证据。终止规则见 99-state-and-handoff.md。
