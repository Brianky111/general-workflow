# 重构路径

重构改的是结构，不是可观察行为。它不是第十二个阶段，而是主线 05 到 09 的另一种走法：每一站的门禁都在，只是要的证据换了形状。LEAN 把 1 到 4 走成一页，重构把 05 到 09 走成一张保护表加一条结构检查。

**重构不是功能。** 它不产生 R-ID 或 A-ID，backlog 一行不动，合同不改。旧版曾把重构记成功能并配上整套文档；这次由脚本拒绝：重构切片里出现 Acceptance 行，或 backlog 把 A-ID 指向重构切片，都报错。

和 08 的 Refactor 步的区别只有一条：改动不出当前切片的 write_scope、不动模块公开入口和边界，就在 08 里做，不需要本文件；要动边界、跨出 write_scope，或者根本没有功能切片在推着它，走本路径。

## 入口

三个入口，区别只在授权从哪来：

| 触发 | 授权是什么 | 收口后回到哪 |
| --- | --- | --- |
| 用户要求重构、整理、拆分、重写本项目 | 用户原话，记进切片文件的 `## Request` | closeout；delivery_target 要发布的走 10 |
| 11 的证据与决策表选定架构演化 | 决策表那一行 | 11 的 closeout 或下一条切片 |
| 07 或 09 发现边界问题：切片被迫绕开既有边界、循环依赖、跨表写入 | 05 重定边界的决策，加当前切片 Blockers 里的记录 | 回到 07，继续那条切片 |

agent 自己发现的重复、坏味道、不够优雅，都不是授权。它们进 03 范围防火墙的后续队列，等用户接受或 11 的决策把它变成上面三种之一。router 的「不自动开启重构」在这里落地：没有 `authorized_by` 指针，状态脚本拒绝这条切片。

接手旧仓库、迁移和线上故障修复仍不在本路径内：它们没有可保护的 A-ID，走 router 第 2 步的兼容面确认。

## 分类

开工前把请求分成三类，一次请求可以同时含两类：

- **纯重构**：可观察结果、公开签名、持久化形状、错误与协议语义、鉴权行为、运行单元归属都不变，只改内部结构。走本路径。
- **行为变更**：上面任意一项会变。这部分不是重构，先走 03 的变更协议拿 C-ID，改验收来源和 backlog，作为功能切片认领。结构部分仍可作为重构切片先做。
- **未受保护**：要保住的行为没有任何测试或调用证据到达它。先补特征测试，再按纯重构走。

分不清就按行为变更处理：错判成纯重构的代价是静默改掉承诺过的行为。

## 保护基线

保护表是重构的验收表。它列的是**已经 delivered、入口路径经过 write_scope 的 A-ID**，不是新行为。

1. 从 write_scope 反查：哪些 delivered A-ID 的真实入口会经过这些路径。切片地图的 path 一节和模块 `AGENTS.md` 的公开入口是查找依据。
2. 在起点 commit 对每条 A-ID 重跑一次它 evidence 里的那次调用，结果写进 baseline 列，形状与 delivered 的 evidence 相同：`<调用> → <观察到的结果> @ <commit>`。这一步就是 99「绿色还在不在」那次校验，只是提前做并落盘。基线跑不绿，先按 03 的变更协议处理那个缺陷，不在重构里顺手修。
3. 没有 A-ID 但必须保住的行为（内部不变量、禁止效果），写成 `P-<n>` 特征行：先写一条对着现有生产入口的特征测试，它现在必须通过，然后同样记 baseline。这是 Red 的反面：证明的是行为存在，不是缺失。
4. 清单有限且冻结。写完就开工，不在执行中继续找不变量；执行中发现漏保的行为，加一行、跑基线、再继续，不回到分类。

基线是脚本硬条件：在途的重构切片，每条保护行都要有 baseline；没有保护行的重构切片被拒。

## 目标结构

目标结构写成 05 的决策：ADR，或 LEAN 的一页决策表加一行。至少写驱动、代价、重评条件。驱动指向触发证据：11 决策表那一行、失败的架构约束检查、或用户原话。

再给它一条**结构检查**：一条现在会失败、改完会通过的命令。依赖方向用 import 检查，数据所有权用 schema 或 grep，模块边界用静态检查或启动探针。它是重构的 Red：起点 commit 的输出记进 before 列，形状是 `<输出> @ <commit>`。写不出这条命令，说明目标结构还没具体到能验证，回到 05。

## 认领与切片文件

认领沿用 07 的认领规则，一条不减；同一个人同时持有功能切片和重构切片的唯一例外也写在那里。重构切片文件名以 `R-` 开头，放在 `docs/workflow/slices/`，字段名与脚本一致：

~~~markdown
# Refactor R-01: <名称>
- owner: <稳定且唯一的标识>
- claimed: <YYYY-MM-DD> / <commit>
- stage: <编号与名称>
- write_scope: <项目相对路径；逗号或分号分隔>
- authorized_by: <C-ID、决策表文档路径#标题，或 docs/workflow/slices/R-01.md#Request>
- decision: <ADR-ID 或决策表指针；脚本不校验>

## Request
<授权来自用户时，原话与日期>

## Protection
| ID | baseline | evidence |
| --- | --- | --- |
| A-03 | `POST /orders {...}` → 201，billing 表新增 1 行 @ 7c1d2e3 | - |
| P-01 | `pytest tests/billing/test_invariants.py -q` → 1 passed @ 7c1d2e3 | - |

## Structure
| check | before | after |
| --- | --- | --- |
| `lint-imports` | 2 条 orders 写 billing 表的违规 @ 7c1d2e3 | - |

## Blockers
- <本切片内部的阻塞；没有就删掉本节>
~~~

脚本对它的规则：

- 与功能切片一样参与一人一条和 write_scope 重叠检查；在途 = 有 owner，且保护表或结构表还有空格。
- `authorized_by` 必填且必须是指针：`C-<n>`、带扩展名的文档路径（可带 `#标题`）或链接。
- 保护行的 ID 是 backlog 里已 delivered 的 A-ID，或本文件内编号的 `P-<n>`；baseline 必填；evidence 填上后，锚点必须不同于 baseline 的锚点——同一个 commit 说明有一次没跑。
- 结构行至少一条；before 必填，after 同样要换锚点。
- 功能切片因这次重构停下来时，在它头部写 `- waiting_on: R-01`；重构收口后没清掉，脚本会提醒。

## 执行

按 08 的循环做，只是 Red 和 Green 换了对象：

- 小步改，每一步跑保护表涉及的测试，全程保持绿；结构检查可以在中途反复，收口时必须绿。
- 提交用 `refactor:` 前缀。**不改断言，不改公开签名。** 改了断言就不是重构，是行为变更，回到分类；改公开签名要先有 C-ID。移动测试文件、改 import 路径不算改断言。
- 范围防火墙照用：邻近的 bug、顺手想加的抽象，进后续队列。
- 触及持久化数据或对外契约的重构，按 10 的迁移与回滚要求准备前滚和回退，即使这次不发布。
- 写入超出 write_scope 时就地修订并重跑脚本；与在途功能切片重叠，按 07 认领规则第 7 条协调。

回滚方式在开工前写进 Blockers 或 decision：一次 revert 的提交区间、一个开关，或新旧并存的切换点。

## 退出门禁

重构切片收口，以下全部成立：

1. 结构表每行 after 已填，锚点是收口 commit，检查确实通过；
2. 保护表每行 evidence 已填，是在收口 commit 上对真实入口重新调用的结果，与 baseline 观察一致；
3. 09 的架构约束检查对涉及的模块通过；公开入口、边界或验证命令变了的模块，其 `AGENTS.md` 已更新；
4. 没有行为变更混进来：契约测试、公开签名和持久化形状与起点一致，或对应的 C-ID 已经在 backlog 里有自己的切片；
5. 状态脚本退出码 0，报告里该切片不再在途；
6. 回到入口表写的那个位置。功能切片在等它的，清掉 `waiting_on`，从它的 stage 继续；用户要求的，按 delivery_target 决定是 closeout 还是走 10。

有在途重构切片时不做任务收尾：99 的「任务结束」把它列为前提。

## 停止条件

出现以下情况停下，回到分类，或向用户提一个决策问题：

- 要保住的行为说不清，或两条已 delivered 的 A-ID 对同一路径的期望互相矛盾；
- 纯重构做着做着需要改断言、签名、持久化形状或错误语义；
- 找不到能写特征测试的接缝，现有生产入口无法在测试环境调用；
- 写入范围不断扩大，超出授权描述的边界；
- 基线在起点 commit 就不绿。

档位只改证据量：LEAN 的减免行在 00-lean-path.md，HIGH-RISK 的加深行在 00-project-profile.md，本文件不复制。
