# 条件深化：高可靠账务、成对不变量与静态上限

本文件基于 `TigerStyle` 的核心安全思想并严格适配上层应用边界，仅在高风险领域按需加载，不盲套嵌入式 C/Zig 教条。

## 触发信号与防教条边界

满足以下任一信号时加载本文件：

- `docs/intent.md` 的 `irreversible_boundaries` 涉及**资金流转、账本计费、额度扣减或法律/审计级不可恢复数据**；
- 自研**存储引擎、网络协议、共识/同步内核或硬实时调度器**。

**防教条声明**：不强迫业务系统放弃成熟运行时去搞“零外部依赖、全静态内存预分配、70 行函数硬切”；成对断言只守在**持久化写入提交与外部存储解码边界**，**严禁**在内部已定型函数间重复做防御性检查或防御按现有契约不可能出现的状态（保持 `02-codebase-guardrails.md` 的边界一次解析、内部信任与错误直接传播纪律），也不得在当前需求未要求时主动追加重试队列或健康检查。

## 守恒定律与读写边界成对断言

1. **把业务不变量写成守恒等式**：不要只写“账务不能错”这类虚话，必须落成可检验的数学/状态守恒律（例如：`借方总额 == 贷方总额`、`可用余额 + 冻结余额 == 累计入账 - 累计出账`、`状态转移严格符合有向无环/授权白名单`）。
2. **读写边界成对断言（Paired Assertions）**：在不变量最容易被悄悄破坏的两个物理边界成对加硬断言——**写入持久化前（Write Commit）**断言入库状态满足守恒等式；**从存储/外部通道读取解码后（Read Decode）**再次断言状态合法。一旦发现磁盘腐败、越界或非法转移当场抛错中止，拒绝带病继续算账或回退默认值。

## 全链路显式资源封顶与背压

任何队列、缓冲区或批处理无上限都会把局部慢请求放大成雪崩内存溢出：

1. **所有可变大小结构写死静态上界**：请求分页 `max_page_size`、批量操作 `max_batch_items`、内存缓冲队列 `max_queue_depth`、单次 Payload `max_payload_bytes`、重试次数 `max_retries` 与外部调用超时 `timeout_ms` 全部落成配置上限并写入 `configurable_params`；
2. **显式背压而不是无限排队**：达到队列或并发上限时立刻返回明确的 `429 / RESOURCE_EXHAUSTED` 可恢复错误信号，让上游退避或降级。

## 确定性仿真接缝（对接深度验证）

为让高风险核心随后能被属性测试（PBT）与状态机模型检测彻底拷打：

- 在模块地图中将**物理时钟（Clock）、随机数生成器（PRNG）与网络/持久化 IO** 收口在极窄的依赖注入接缝之后；
- 确保核心账本/状态机可在单线程下用固定随机种子重放消息乱序、重复投递、半途崩溃与超时，并与 `03-verification-and-artifacts.md` 中的 PBT / TLA+ 检验直连。

## 高可靠深化门禁

离开本文件回填 `01b-dataflow-and-contracts.md` 前核对：

1. 核心账务/状态守恒等式已写入 `docs/intent.md` `invariants` 与 `docs/arch/dataflow.md`；
2. 写入落盘与读出解码处的成对不变量断言点已落入 `docs/arch/contracts.md` 设计；
3. 所有队列、批量、重试与超时上限均已有静态数字界定并进入 `configurable_params` 与失败矩阵，核心状态机已预留可确定性重放的时钟/随机/IO 接缝。
