# 技术栈、仓库脚手架与基础 CI

本阶段把已接受的架构选择落成一个能在干净环境中运行的仓库。脚手架的目的不是提前写完所有层，而是尽早暴露依赖、配置、构建和部署问题。

## 目的与入口

目的：建立可重复的本地开发、测试、构建和合并路径，为第一条垂直切片提供真实组合根。

入口：

- 05-architecture-design.md 已通过 Architecture Ready；
- 语言、框架、数据库、消息/缓存、部署目标和目录边界已有具体选择或明确“不需要”；
- 关键风险实验没有未处理的失败。

## 落地顺序

### 1. 固定具体版本

把架构中的抽象名词变成可安装版本，并提交锁文件：

- 语言运行时和包管理器；
- Web/CLI/移动/任务框架；
- 数据库、ORM/驱动、队列/缓存客户端；
- formatter、linter、typecheck、测试和构建工具；
- 容器基础镜像、CI runner 和部署工具。

每个主要选择在 README 或 ADR 中写理由、许可证、升级节奏、已接受的代价和替换条件。避免把“latest”作为可复现依赖。

### 2. 使用官方脚手架

优先使用框架官方初始化器或组织批准的模板，然后删除不需要的示例和默认依赖。脚手架命令应可重放；若模板生成了不可解释的配置，补一段 README 说明。

### 3. 建立最小目录

目录应反映 05 阶段的边界。可以先有启动、配置、一个业务模块和测试入口，不要创建没有调用方的空层、未来服务或“万能 utils”。

至少保证：

- 一个明确的组合根/启动入口；
- 生产代码与测试、脚本、迁移、文档的边界；
- 配置、秘密和环境文件的约定；
- 数据库/队列等本地依赖的启动方式；
- 真实 API/CLI/worker 入口可以被测试和本地命令调用。

维护根 `AGENTS.md` 中的项目通用指令和模块导航：修改目标路径前发现并读取适用的上级与嵌套指令；跨模块切片读取各自规则。保留既有指令及 override，不假设所有子目录文件都已自动加载。模块指引的创建和维护规则见 07-vertical-slice.md。

### 4. 配置工程质量

配置 formatter、linter、类型检查（适用时）、测试发现、覆盖率基线和提交前检查。规则应能自动修复常见格式问题，但不能把 lint 关闭当作快速通过。

提供：

- .env.example（无秘密、说明每个变量和默认值）；
- 本地数据库/缓存/队列的 docker compose 或等价启动说明（只有确有依赖时）；
- 数据库迁移和种子数据命令；
- 健康检查或最小启动探针；
- 统一的日志和 request ID 初始化。

### 5. 定义可重复命令

README 至少列出这些命令及其前置条件：

~~~text
setup    安装锁定依赖并准备本地环境
format   格式化或检查格式
lint     静态检查
typecheck（适用时）
test     单元测试
test:integration（有真实依赖时）
build    生成可部署产物
check    运行合并前的最小全套检查
dev      启动真实开发入口
~~~

命令失败时应返回非零状态，并说明如何诊断。不要让“本地手工点几下”成为唯一启动步骤。

### 6. 尽早接入基础 CI

第一条切片前至少有一条 push/PR 流水线（还没有远端或 CI 提供方时见本节末尾）：

~~~text
checkout
  -> install locked dependencies
  -> format check
  -> lint/typecheck
  -> unit tests
  -> build
  -> publish logs/artifacts
~~~

CI 使用干净环境，不依赖开发者机器的缓存或未提交文件。集成测试若需要数据库/队列，可在 CI 中启动隔离依赖；E2E、性能和生产部署按风险在后续阶段增加。

CI 与 CD 的边界要清楚：CI 证明提交可合并和产物可构建；CD 在 10-release-operations.md 中负责 staging/production 晋级、迁移、发布、观察和回滚。

**还没有远端仓库或 CI 提供方时**：把流水线定义照常提交，并在干净目录里按同样顺序跑一遍
等价命令，记录命令、版本和结果；在状态里记 `ci: local-only` 为未决事项，首次 push 后复验。
不能省的是“同一组命令能在干净环境里从零跑通”，不是某个托管服务。

### 7. 干净 clone 验证

由未配置过项目的人或一个临时目录执行 README 步骤：

1. clone 指定提交；
2. 运行 setup；
3. 启动必要本地依赖；
4. 运行 check、build 和最小健康检查；
5. 记录系统、运行时和耗时。

失败就修脚手架或文档，不要让第一条切片承担基础环境排错。

## Bootstrap Ready 门禁

进入 07-vertical-slice.md 前必须有：

- 锁定版本和可追溯的技术选择；
- 最小但真实的目录/组合根；
- formatter、lint、测试、构建和（适用时）类型检查；
- 无秘密的环境模板和本地依赖说明；
- 一组可复制的 setup/format/lint/test/build/check 命令；
- 基础 CI 至少成功运行一次，或按上面的本地等价方式记录一次并留下未决事项；
- 干净 clone 能启动并通过最小检查；
- 不存在因“以后再说”而误导调用方的空层或平行生产入口。
